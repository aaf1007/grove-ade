# 0013: Chat mode by default, terminal mode as the fallback

- Status: Accepted (Nov 2026). Supersedes 0003.
- Context: ADR 0003 ran agents only as their TUIs, so new agent features worked on day one. The developer now wants a GUI chat: messages, tool calls, approvals and questions drawn by grove, with an editor beside them. Both agents now have documented programmatic interfaces (the Claude Agent SDK and `codex app-server`) that load the user's own config, skills and MCP servers. They still miss some TUI-only features: Claude's `/login` and `/theme`, plugins installed from a marketplace, and some slash commands.
- Decision: An agent session runs in one of two modes. Chat mode is the default: grove drives the agent through its protocol (ADR 0015) and draws the conversation itself. Terminal mode resumes the same conversation in the agent's real TUI in a PTY (`claude --resume`, `codex resume`). The user switches per agent session. A conversation runs in one mode at a time: switching ends one process and resumes the conversation in the other.
- Consequences: grove owns a chat UI and must keep up with each protocol. Terminal correctness stays a hard requirement, now for terminal mode, shell, run and command panels. The PTY pipeline, snapshots and the headless parser stay. Status heuristics and agent snapshots matter only in terminal mode. The review batch becomes a chat message in chat mode and stays a bracketed paste in terminal mode.
- Revisit if: either protocol stops loading the user's config, skills or MCP servers, or terminal mode becomes the mode the developer uses most during dogfooding.
